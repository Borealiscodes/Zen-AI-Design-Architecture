## **1. Rendering Purpose**
These specifications define the **geometry**, **color**, **interaction**, and **provenance** rules for all PNG assets produced across:

- Zen‑AI‑Design‑Architecture  
- NDH‑CORE Governance  
- TISD (Trauma‑Informed‑Systems‑Design)  

They ensure:

- consistency  
- clarity  
- accessibility  
- trauma‑sensitive visual pacing  
- cross‑repo alignment  
- stable iconography  

This is the **authoritative rendering layer** for the constellation.

---

# **2. Core Rendering Invariants**

These invariants apply to *all* PNG assets, regardless of repo.

### **2.1 Geometry Invariants**
- Curves must be **vector‑safe**, smooth, and non‑jagged.  
- Holonomy arcs must form **closed loops** with no sharp discontinuities.  
- Soft‑manifold surfaces must use **translucent layering** with reversible traversal lines.  
- Governance emblems must maintain **bilateral symmetry**.

### **2.2 Color Invariants**
- Use the **Enso Gradient** for Zen assets (white → indigo → black).  
- Use **Governance Neutrals** for NDH‑CORE (graphite, slate, obsidian).  
- Use **Trauma‑Informed Palette** for TISD (soft blues, muted greens, warm neutrals).  
- Transparency must be **consistent across layers** (0–40% opacity).

### **2.3 Interaction Invariants**
- Contact gestures must be **minimal‑intervention**.  
- Overlays must be **non‑dual**, meaning no hard boundaries.  
- Traversal lines must be **reversible**, indicating safe return paths.

### **2.4 Provenance Invariants**
- Every PNG must include:
  - repo watermark  
  - version mark  
  - rendering profile ID  
  - constellation signature
