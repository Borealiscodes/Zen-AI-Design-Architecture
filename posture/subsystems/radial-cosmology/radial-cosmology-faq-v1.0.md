# 🌌 **Radial Cosmology Subsystem FAQ — v1.0**

## 🧭 Core Concepts

### **1. What is the Radial Cosmology subsystem?**  
It is a **self‑contained rendering pipeline** inside the posture layer that transforms a mythic radial cosmology into formal blueprints, manifests, vector geometry, and a final transparent PNG.  
See: **Radial Cosmology**

### **2. Why is the cosmology radial?**  
Radial geometry ensures **symmetry**, **narrative hierarchy**, and **consistent coordinate derivation** across rings.  
See: **Radial Layout**

### **3. What are the four node classes?**  
- **Central** — origin point  
- **Mountain** — planetary peaks  
- **Story** — narrative derivatives  
- **Meta** — abstract thematic nodes  
See: **Node Class**

---

## 📐 Geometry & Rendering

### **4. How are node positions determined?**  
All nodes are placed using fixed radii and angles, then converted to Cartesian coordinates in the **Coordinate Table**.

### **5. What is the JSON Rendering Manifest?**  
A renderer‑agnostic contract containing nodes, edges, coordinates, and style rules.  
See: **JSON Manifest**

### **6. Why generate an SVG before the PNG?**  
SVG provides **inspectable vector geometry**, ensuring accuracy before rasterizing.  
See: **SVG Geometry Spec**

---

## 🧩 Graph Logic

### **7. How are connections between nodes defined?**  
Through the **Adjacency Matrix**, which encodes all permitted edges.  
See: **Adjacency Matrix**

### **8. Why does the cosmology use a graph?**  
Graphs express **narrative relationships**, **symbolic dependencies**, and **structural symmetry**.

---

## 🏛️ Subsystem Architecture

### **9. How does this subsystem fit into the posture layer?**  
It is one of the posture layer’s structured visualization engines.  
See: **Subsystem Overview Diagram**

### **10. What directories does the subsystem contain?**  
- **Blueprints** — specs, coordinates, adjacency, manifest, SVG  
- **Renders** — PNG output

- **Index** — master index

## 🧭 Usage & Extension

### **14. Can new rings or node classes be added?**  
Yes — the subsystem is extensible. New rings require updates to:  
- Rendering Spec  
- Coordinate Table  
- Adjacency Matrix  
- JSON Manifest  
- SVG Spec  
See: **Rendering Spec**

### **15. Can the cosmology be rendered in other styles?**  
Yes — by modifying the style block in the JSON manifest and regenerating the SVG.

### **16. Can this subsystem be reused for other cosmologies?**  
Absolutely. It is designed as a **generalizable radial rendering engine**.
